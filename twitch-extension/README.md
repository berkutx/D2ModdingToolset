# Disciples II Battle Info · Twitch 0.0.1

Расширение показывает зрителю рамки боевых юнитов и карточки с параметрами, способностями и действующими эффектами при наведении. Зритель пользуется расширением в Twitch; устанавливать игру или плагин на его компьютер не нужно.

## Установка для стримера

Нужны Windows, поддерживаемая сборка Disciples II Russobit/MNS с совместимым C4dllR, OBS и Twitch. Первый режим рассчитан на боевой интерфейс `DLG_BATTLE_B` и полный клиентский кадр одного окна игры. Обрезка, произвольное размещение игры в сцене, дополнительный Ctrl+Wheel zoom и внутренние чёрные поля враппера пока не поддерживаются геометрией оверлея.

1. Полностью закройте игру и установите комплект **C4dll-R 2.0** по его `INSTALL.txt`. В комплект уже входят `Mods/timer.c4p` и `Mods/twitchstat.c4p`. При обновлении сохраните свои настройки; не заменяйте существующий `C4Plugins.ini` примером из архива.
2. Запустите игру и включите **Twitch Stat** в меню плагинов. Встроенное соединение с браузером запускается вместе с плагином; Node.js и отдельный процесс моста не нужны.
3. Установите расширение Twitch и активируйте его как **Video Overlay**. Пока версия находится в Hosted Test, аккаунт должен входить в Testing Account Allowlist.
4. В панели управления трансляцией откройте Live Configuration расширения и нажмите **Подключить игру**. Разрешите появившееся окно соединения и проверьте показанный PID игры.
5. Оставьте панель Twitch и окно соединения открытыми на время эфира. В OBS захватывайте только полное игровое изображение без обрезки и смещения. Проверенный исходный режим — клиентский кадр 1366×768, растяжение окон 100%.

Пошаговая инструкция без инструментов разработчика: [STREAMER-RU.md](STREAMER-RU.md). Она включается в архив враппера под именем `TWITCH-STREAMER-RU.md`.

Для ручной настройки существующего `C4Plugins.ini` можно использовать `[TwitchStat]` с `Enabled=1`, `Preview=0`, `Profile=0`. `Profile=1` включает диагностический замер, а `Profile=2` дополнительно останавливает сбор после двадцати полных снимков до перезапуска игры. Для эфира оставьте `Profile=0`.

Соединение слушает только `127.0.0.1:8765` и передаёт данные этого игрового процесса. Если запущены несколько клиентов, включайте Twitch Stat только у того, который показываете в OBS; проверяйте PID в окне соединения. При занятом порте не запускайте второй мост и не подменяйте источник автоматически: выключите Twitch Stat в другом клиенте или завершите прежний диагностический Node-мост, затем включите плагин у нужной игры.

Если браузер сообщает об отсутствии соединения, проверьте, что игра запущена и Twitch Stat включён, затем подключитесь заново из Twitch. Вне поддерживаемого боя или при устаревших данных карточки скрываются. Закрытие панели Twitch прекращает доставку карточек; игра и видео продолжают работать.

## Как устроена передача

`twitchstat.c4p → локальное окно соединения → панель Twitch → Twitch PubSub → зрительский оверлей`.

Локальный HTTP/SSE-сервер и одиннадцать файлов интерфейса встроены непосредственно в `twitchstat.c4p`. Отдельные HTML/JS-файлы на компьютере стримера не требуются. Сетевой поток использует опубликованный снимок боя и не вызывает игровые функции. Плагин выполняет получение игровых карточек порциями в потоке интерфейса игры.

Панель отправляет снимки через Twitch Extension Helper. Собственный публичный сервер, OAuth-приложение и секрет Twitch в клиенте не нужны. Здоровье и эффекты приходят со снимками; оверлей учитывает сообщаемую Twitch задержку видео. Это не гарантия покадровой синхронизации.

## Состояние проверки

- Автоматические проверки: **48 веб-тестов**, **18 проверок допуска захвата**, **16 проверок нативного транспорта** и **21 проверка упаковки релиза**. Нативные проверки включают настоящий `.c4p`, переключение Enabled, 11 встроенных ресурсов, HTTP/SSE, устаревание данных, занятый порт и отключение клиентов.
- Встроенный сервер проверен на живой игре без Node: получены полные снимки шести юнитов, доставка браузерному слушателю Twitch и карточки локального оверлея. Отдельно исправлен отказ первого захвата при уже открытом локальном выборе и оставшемся флаге анимации; проверки переходов и состояния до/после захвата сохранены.
- Компактная полупрозрачная карточка шириной до **460 px** проверена в браузере при ширине окна **1366, 640, 400 и 320 px**. Обновление данных сохраняет фокус и раскрытый блок описания.
- Пользователь подтвердил работу в настоящем тестовом эфире с прежним отдельным Node-мостом. Сквозной эфир с текущим встроенным сервером и новым компактным интерфейсом отдельно ещё не подтверждён.
- Twitch-версия **0.0.1** находится в **Hosted Test**. Обновлённый веб-пакет с компактной карточкой и инструкциями загружен 20 сентября 2026. Review и публичный Release расширения не выполнялись.

## Сборка и пакеты

Исходники плагина: [unitinfo](../c4ddraw/plugins/unitinfo/). Проект `unitinfo.vcxproj`, конфигурация `Release|Win32`, собирается MSBuild/Visual C++ с Windows SDK; CRT статический (`/MT`). Сетевые зависимости входят в Windows (`ws2_32`). `bridgeassets.rc` включает файлы из этого каталога напрямую при сборке, без генератора на Node.

Основной `c4ddraw/build.ps1` собирает враппер и оба плагина. Релиз `c4dll-r-v2.0` включает Twitch Stat в общий архив враппера; отдельный публичный релиз плагина не требуется. Версия веб-расширения Twitch остаётся `0.0.1` и проходит собственный Review/Release.

Из каталога `twitch-extension` можно подготовить веб-пакет:

```powershell
.\tools\package-extension.ps1
```

`tools/package-plugin.ps1` сохранён для технической передачи отдельной сборки: он создаёт ZIP только с `Mods/twitchstat.c4p` и `README.txt`, сам игру не обновляет. Основной пользовательский дистрибутив — архив **C4dll-R 2.0**, содержащий враппер, оба плагина и инструкцию стримера.

`dist/disciples-2-battle-info-0.0.1.zip` содержит девять веб-файлов для загрузки на Twitch. Локальные `relay.html` и `relay.mjs` туда не входят: их обслуживает плагин. Этот ZIP не устанавливается в игру и не включается в пользовательский архив враппера.

Для разработчика сохранён прежний `bridge/server.mjs` как средство проверки протокола. Node.js 24 нужен только для этих тестов/инструментов:

```powershell
node --test test/*.test.mjs
.\tools\test-native-bridge.ps1
```

Не запускайте диагностический Node-мост одновременно со встроенным сервером на порту 8765.
