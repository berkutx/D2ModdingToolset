# Проверка native-границы локального тестового координатора

## Задача и область

Харнес переносится отдельным изменением поверх `codex/prepared-simturns`
(`51eacdb745c78b927c24c1f3c9dc004a044695e3`). Источник рабочего набора —
`feature/simturns-on-test-harness`, commit
`b7637a031e307e19b2df6d817783f23dabce540e`.

Локальные тесты и лобби используют один `CoordinatorPort` и одно игровое ядро ОХ.
В production нет переменных среды для включения pipe. Новый адаптер находится
в `testdrv/local_coordinator_adapter.cpp`, компилируется только при `D2TestDrv=true`
и выбирается явно для локального теста. Он не заменяет авторизованный lobby Arm.

## Проверенные native-факты

Исследован Russobit `Discipl2.exe`, 4 187 648 байт, SHA256
`1375cdef09ec470ee64fe5693fb734d7c69fb215212311d997f792b258a642eb`.
Дизассемблирование IDA сверено с байтами фактического PE-файла.

| Факт | Проверенное место |
| --- | --- |
| `CreateNetClient`: `ECX=this`, два stack-аргумента `name/bool`, результат net-player ID в EAX | Вход `0x403200`, `ret 8` в `0x403338` |
| Первые две полные инструкции, 10 байт | `B8 A4 6A 68 00 E8 C6 A1 26 00`, file offset `0x2600` |
| Join создаёт/выбирает сессию и устанавливает роль до создания клиента | `0x4F01FD` вызывает `0x4030B3`, `0x4F0209` вызывает `0x403863`, затем `0x4F0232` вызывает `CreateNetClient` |
| Host создаёт сервер до клиента | `0x4EA42E` вызывает `0x403617`, затем `0x4EA457` вызывает `CreateNetClient` |
| Host-флаг устанавливается при создании сервера | `0x4036C1`, поле `data+32` |

Вывод: typed-hook `CreateNetClient` даёт причинную границу для локального arming:
сессия и роль уже определены, нативный клиент ещё не создавался. Вход проверяется
до общей транзакции установки хуков. Псевдокод декомпилятора для этой функции не
использован как доказательство: неверная `noreturn`-разметка аллокатора обрезает его.

## Жизненный цикл и доставка

1. Первый обычный UI-callback запускает pipe worker и Hello, не из `DllMain`.
2. Локальный `CreateNetClient` проверяет DirectPlay-сессию и роль, затем вызывает
   test-only `armLocal` и тот же production `beginSession`.
3. Координатор отвечает на Hello только HelloAck. SessionPlan появляется после
   регистрации обоих ненулевых player handles; эти handles возникают позже при
   создании игровой фазы. Следовательно, Hello сам по себе не запускает день ОХ.
4. Успешный Sender означает принятие в ограниченную FIFO, как транспортный Send,
   а не подтверждение физической записи или получения другим клиентом. Частичная
   запись/ошибка pipe терминальна. Все overlapped-операции отменяются и завершаются
   до уничтожения их буферов.
5. До native-clear прекращается приём; после native teardown завершается worker.
   Автоматического reconnect или продолжения повреждённой эпохи нет.

`armLocal` отличается от lobby Arm только получением epoch/merge day из первого
валидного ОХ SessionPlan. Stock downgrade, повторный план, нулевая эпоха и
недопустимый день не принимаются. Portable-тесты проверяют оба варианта порта:
обычный и собранный с `D2_TESTDRV`.

## Граница доказательств

При повторном ревью устранены две связи, искажавшие обычную приёмку:

- Формат `EXACT_LEGACY_MOVES` больше не включает синхронный host loopback.
  Формат пути/MP сохранён, транспорт остаётся штатным. Старый маршрут доступен
  отдельно через `LEGACY_HOST_LOOPBACK` только для диагностического сравнения.
- Парный EndTurn хранит единственное pending-намерение, но не блокирует UI.
  Между arm и release продолжаются обычные кадры и RX. После release проверяются
  текущие identity, право хода и native idle в пределах прежнего deadline;
  подтверждение результата выдаётся только после возвращения native callback.

Проверка старта больше не ищет удалённый `roleHint` в DllMain-preflight.
Она требует ровно одну подготовку both-role bundle и ровно один штатный
`room armed before native startup (role=host|join)` в каждом собственном PID-журнале.
Этот второй маркер следует за успешным `beginSession`, до создания клиента и до
удерживаемого SessionPlan. Проверки роли, порядка, таймаутов и release не удалены.

Дизассемблирование подтверждает ABI, адреса и порядок native-вызовов. Portable
проверки подтверждают автомат состояний и wire-контракт, но не заменяют живую игру.
Исторические 18 сценариев не объявляются новым результатом лобби. Фиксированная
экспортированная карта старой кампании и generated-map lobby bootstrap — разные
предусловия; команды и актуальная матрица покрытия находятся в
[TEST_HARNESS.md](TEST_HARNESS.md).
