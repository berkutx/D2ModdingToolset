живой прогон выявил следующий предыгровой отказ на `CCmdUpdateObjMsg`.

## Вывод и дальнейшая проверка

**F1, подтверждён E1/E2:** отсутствие MSS-owned binding в reporter блокировало
автоматический вход. Исправлено и проверено в настоящих клиентах.

**F2, подтверждён E3/E4/E5:** текущий native completion contract отвергает
обновление, возникшее из разрешённого штатного начального переименования лидера,
пока джойнер ещё не создал игрового consumer. Это не неверный пароль, не повтор
раннего JoinGame и не падение процесса.

Путь P1: `host BTN_CLOSE` → `CStackChangeLeaderNameMsg` → native server
`CCmdUpdateObjMsg + CRefreshInfo` → join menu `Unhandled` → Protocol Abort
→ remote Abort хоста. Каждая связь наблюдается в E3/E4.

Нельзя просто задержать completion: пакет уже прошёл dispatch без обработчика,
а completion не хранит его для повторного применения. Нельзя также глобально
превратить `Unhandled` в `Applied`: меню/активация и причинные ACK остаются обязательными.
Для исправления требуется подтвердить native consumer/формат UpdateObj и его
отношение к последующему полному снимку NewScenario. Такое изменение в этой
поставке не сделано; проверки sender, lifetime, snapshot boundary и fence не ослаблены.

Результат: **login/подготовка проверены; production bootstrap, первый одновременный
ход, объединение, бои и прежняя кампания 18/18 не пройдены.** Тестовая подготовка
закрыта через endpoint без результата/рейтинга; её история и журналы сохранены.
