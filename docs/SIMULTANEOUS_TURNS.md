# Одновременные ходы через лобби

MSS исполняет игровые операции ОХ, а авторизованный сервер лобби управляет днями,
допусками хода и объединением в обычные ходы.

**Нужна серверная реализация [контракта ОХ](SIMULTANEOUS_TURNS_LOBBY_PROTOCOL.md).**
Этот PR добавляет клиент и спецификацию, а не готовый сервер. Успешная сборка и
протокольные тесты не означают приёмку двух клиентов через настоящее лобби.

## Собрать клиент

После обычной подготовки зависимостей проекта, в Developer PowerShell для x86:

```powershell
msbuild mss32/mss32.vcxproj /t:Build /p:Configuration=Release /p:Platform=Win32 /p:EnableSimultaneousTurns=true
```

`EnableSimultaneousTurns` по умолчанию `false`. Включение добавляет `D2_SIMTURNS`
и игровые модули ОХ. Та же настройка поддерживается в `Debug`; это не режим
тестирования. Смена конфигурации не включает `D2_TESTDRV`.

| Выбор | Назначение | Кто управляет |
| --- | --- | --- |
| Debug / Release | Оптимизация и отладочная информация | Сборка |
| EnableSimultaneousTurns | Наличие реализации ОХ в DLL | Сборка |
| ОХ конкретной комнаты | Участники, роль, эпоха, день объединения | Сервер лобби |
| D2TestDrv | Автоматизация действий и наблюдение | Отдельная опция сборки, [инструкция](TEST_HARNESS.md) |

Production-клиент (`D2TestDrv=false`) не включает ОХ через переменные среды и не
подключается к локальному pipe.
Наличие реализации в DLL само по себе не изменяет обычную игру. Сервер должен
подтвердить возможность ОХ у обоих участников до запуска карты.

## Поддерживаемая игровая область

- Проверенный Russobit EXE: 4 187 648 байт, SHA256
  `1375cdef09ec470ee64fe5693fb734d7c69fb215212311d997f792b258a642eb`.
- Два человека: хост и присоединившийся игрок; новая карта с первого дня.
- День объединения `0` означает ОХ без объединения; `2..30` — объединение
  перед началом указанного дня. День `1` не поддерживается.
- Другой EXE остаётся пригодным для обычного режима, но не объявляет поддержку ОХ.
- Восстановление сохранённого активного ОХ-сеанса, переподключение к той же эпохе,
  третья человеческая сторона и миграция хоста не поддерживаются.

После принятия ОХ ошибку нельзя скрыть переходом на обычные ходы. Штатный переход
`ReleaseStock` возможен только после подтверждённого объединения обоих клиентов.

## Размещение кода

| Область | Ответственность |
| --- | --- |
| `mss32/src/simturns/controller.cpp`, `state.cpp` | Допуски действий, игровые подтверждения, жизненный цикл карты |
| `engine_hooks.cpp`, `day_scope.cpp`, `spell_timing.cpp`, `battle_compat.cpp`, `patches.cpp` | Игровые изменения ОХ, сохранённые из исходной реализации |
| `control_client_core.cpp`, `protocol.cpp`, `turn_context.cpp` | Независимый от транспорта v8-клиент |
| `coordinator_port.cpp` | Контракт доставки и завершения, без pipe и тестовых команд |
| `lobby_transport.cpp`, `lobby_wire.h` | Авторизованная комната, эпоха, упаковка v8 в существующее соединение |
| `netintercept.cpp`, `uiframedispatcher.cpp` | Узкие точки обычной доставки и выполнения действий в игровом UI-потоке |
| `tools/simturns-relay` | Эталонный локальный координатор и его регрессионные тесты |

По умолчанию харнес использует штатную отправку движения, а не синхронный вызов
серверного обработчика. Исторический диагностический маршрут доступен только при
явном `D2TESTDRV_LEGACY_HOST_LOOPBACK=1` и не является обычной приёмкой транспорта.
`D2TESTDRV_EXACT_LEGACY_MOVES` выбирает только старый формат намерения движения,
сохраняя геометрию и проверки MP; сам по себе он не меняет способ доставки.
Тестовые команды и fixture-подготовка компилируются только с `D2TestDrv=true`.
Харнес использует то же ядро ОХ через локальный координатор или настоящее лобби;
запись видео для этих сценариев не требуется. Описание и границы покрытия — в
[TEST_HARNESS.md](TEST_HARNESS.md).

## Проверить протоколы

Из корня репозитория в Developer PowerShell x86, с установленными submodules:

```powershell
./tests/run-simturns.ps1 -OutputDirectory ./artifacts/simturns-tests
./tests/run-prepared-match-protocol.ps1 -OutputDirectory ./artifacts/prepared-tests -DependenciesRoot (Get-Location).Path
Push-Location tools/simturns-relay
try { node --test } finally { Pop-Location }
```

Node.js нужен только тестовым инструментам, не production DLL. В CI сохраняются
Debug и Release с ОХ и без него; отдельно собираются DebugTest с ОХ/без ОХ и
Release с ОХ и харнесом. Протокольные тесты выполняются один раз.
Исторические 18 live-сценариев относятся к исходному pipe-транспорту и не
подменяют будущую проверку лобби. Объём переноса и проверок описан в
[отчёте](2026-09-22_simturns-port-report.md).
