# Загрузка хода джойнера: блокировка интерфейса хоста

Дата: 2026-09-12. Причина и исправление подтверждены статическим разбором;
полный игровой прогон новой DLL ещё требуется. Таймерный пропуск хода не заменяет
проверку обычного ввода мышью.

## Область работы

Пользователь запросил исправить загрузку сетевого сейва с продолжением хода джойнера,
после которого хост получает правильный день/доход, но сохраняет WAIT и не может действовать.
Изменения ограничены MSS текущей ветки `codex/lobby-restart`.
Другие DLL, Lua, диалоги, формат сейва и сетевой протокол не меняются.
Серверные команды `gg`/`save` исправлены отдельно в D2LobbyServer commit `fc819b9`.

Анализируемый файл: `C:\GOG Games\slasher_mns_2_4 - Copy\Discipl2.exe`,
PE x86 Russobit, 4 187 648 байт, SHA256
`1375CDEF09EC470EE64FE5693FB734D7C69FB215212311D997F792B258A642EB`.
Инструменты: существующий экспорт IDA и независимая проверка машинных инструкций
через pefile 2024.8.26 / Capstone 5.0.1. Игра для анализа не запускалась.

## Findings — выводы

### F1: двойная первоначальная блокировка

Критичность: P1 (нельзя управлять хостом после передачи хода).
Статус: причина подтверждена, уверенность высокая. Evidence: E1–E6, E9.
Место: initial BeginTurn загруженного сетевого матча и CStratInterf::Notify1.

Конструктор уже установил полный запрет ввода, но оставил mode=0. В обычном host-first
bootstrap это согласовано с последующим собственным TurnInfo. При возобновлении
чужого хода первый BeginTurn видит ещё не активированного джойнера как AI:
mode 0 → 2 добавляет вторую блокировку. Первый свой TurnInfo снимает одну, остаётся одна.

Нейтралы не исключение: в наблюдаемой очереди три native-записи, а не только два человека.
Поэтому простое удаление подмены initial BeginTurn не является общим исправлением:
переход к нейтралам перед хостом тоже может добавить блокировку при mode=0.

### F2: исправлять режим, не принудительно включать ввод

Критичность: n/a_re. Статус: подтверждённый способ согласования состояний,
уверенность высокая; игровая приёмка отдельно. Evidence: E4–E8.
Место: `prepareLobbySaveResumeUi`, вызов из существующего ObjectLock::Notify1.

Перед первым адресованным хосту BeginTurn чужого игрока режим устанавливается в
`Full=2`, если UI всё ещё в Initial и положительные native counters подтверждают
уже взятую блокировку. Сами counters не меняются.

Ограничения: Russobit и custom lobby; хост; та же очередь и CMidObjectLock;
точные RTTI фазы/интерфейса; recipient пустой либо локальный; activePlayer не локальный;
clientTakesTurn=false; сохранённая переменная CONCLAVE_TURN_BASE присутствует.
LAN/одиночная игра, обычное начало своей партии и сообщения другим адресатам не затрагиваются.

| Следующий штатный переход | Результат |
| --- | --- |
| Full → AI/Full | Блокировка остаётся одной: дополнительного инкремента нет. |
| Full → Human | Native снимает полную блокировку и ставит CTaskWait. |
| Human → AI/Full | Native убирает CTaskWait и берёт одну полную блокировку. |
| Первый собственный TurnInfo | Native снимает ровно существующую блокировку / CTaskWait. |

## Path — путь вызовов

P1, callflow: load (E1) → старт хоста раньше джойнера (E2) →
состояние с ещё AI-джойнером и initial BeginTurn (E3) →
ObjectLock::Notify1 подготавливает Full (E7–E8, F2) →
StratNotify1 выполняет штатный переход (E5) →
нейтралы/другие участники → свой BeginTurn/TurnInfo (E6) → ввод хоста разрешён.

Порядок native-очереди, loadedTurnOffset, граница дня, ресурсы, позиции и MOVE не меняются.
Поле BeginTurn.activePlayerId вынесено в одну общую декларацию CCmdBeginTurnMsg
(20 байт, payload +16), используемую и серверным resume hook, и проверкой UI.
Пакеты не добавляются и не переупорядочиваются; новых hooks/адресных API нет.

## Воспроизведение статической проверки

В окружении с установленными pefile и capstone следующий Python-код проверяет EXE
и печатает ключевые диапазоны с известных границ функций:

```python
from pathlib import Path
import hashlib
import pefile
from capstone import Cs, CS_ARCH_X86, CS_MODE_32

target = Path(r"C:\GOG Games\slasher_mns_2_4 - Copy\Discipl2.exe")
assert hashlib.sha256(target.read_bytes()).hexdigest().upper() == (
    "1375CDEF09EC470EE64FE5693FB734D7C69FB215212311D997F792B258A642EB")
pe = pefile.PE(str(target), fast_load=True)
image, base = pe.get_memory_mapped_image(), pe.OPTIONAL_HEADER.ImageBase
decoder = Cs(CS_ARCH_X86, CS_MODE_32)
for start, end in [(0x422D3D, 0x422DC7), (0x42BC1A, 0x42BCD1),
                   (0x405C5E, 0x405CC3), (0x48D02C, 0x48D3E9),
                   (0x491637, 0x4917B4), (0x490D53, 0x490E45)]:
    for ins in decoder.disasm(image[start-base:end-base], start):
        print(f"{ins.address:08X}  {ins.mnemonic} {ins.op_str}")
```

Требуется локальная копия этого EXE; бинарник и игровые журналы в Git не включены.
Экспорт IDA помечает некоторые функции как noreturn ошибочно, поэтому инструкции
после таких вызовов проверялись непосредственно по EXE.

## Приёмка новой DLL

Release|Win32 собрана MSBuild/v143: 0 ошибок, 4 прежних C4018 в menurandomscenario.cpp.
DLL: 6 493 184 байта, SHA256
`915B4518DCABE6BAB6C6D830CE7AD505A353B998BBC22F3DD4F9FF9237E5D75D`.
Проверена модель native-переходов для 126 последовательностей Human/AI перед
первым ходом хоста: Full сохраняет баланс, исходный путь AI/AI воспроизводит лишний lock.
Это проверка арифметики по дизассемблеру, не запуск игры.

1. Загрузить сетевой сейв с хода джойнера. Он должен продолжить свои движения, без
   повторного дохода/начала дня. В mss32.log хоста ожидается одна строка
   `Lobby resume: initialized host UI wait` для первоначального интерфейса.
2. Завершить ход джойнера, дождаться нейтралов. После окна начала хода хост должен
   двигать отряд, открывать интерфейсы и вручную завершать ход; день и доход остаются верными.
3. Проверить следующий круг; загрузку своего хода; вариант с несколькими людьми/AI.
   Арифметика нескольких игроков проверена по native-переходам, живой прогон ещё не выполнен.
4. Проверить gg и ручной save в casual-загруженной комнате после обновления сервера.
   В casual файл сейва остаётся у хоста, рейтинг не начисляется.

Хронология: прочитаны логи → отдельно подтверждён живой native-ход и UI-блокировка →
проверены загрузка/human и порядок bootstrap → исключены cursor-force и отложенные
пакеты → внесено согласование waitMode. Успешная компиляция не заменяет пункты 1–3.
